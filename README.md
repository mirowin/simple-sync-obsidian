# Simple Encrypted Sync для Obsidian

Плагин синхронизирует одно хранилище Obsidian между компьютером и Android-телефоном через ваш VPS. В комплект входит веб-просмотрщик Markdown с доступом только для чтения.

## Что уже работает

- автоматическая синхронизация каждые 30 секунд и через 2 секунды после изменения файла;
- заметки, изображения, PDF и любые другие файлы хранилища;
- сквозное шифрование AES-256-GCM: сервер не получает ключ, имена файлов или открытое содержимое основной копии;
- проверка целостности SHA-256;
- безопасное разрешение конфликтов через отдельную `conflict-...` копию;
- подключение второго устройства одним секретным кодом;
- отдельная веб-копия только выбранных файлов;
- иерархический проводник папок и подпапок с сохранением раскрытых разделов;
- полнотекстовый поиск по разрешённым заметкам, светлая и тёмная темы, мобильная вёрстка;
- Markdown, свойства, Obsidian `[[wiki links]]`, вложения заметок и файлов `![[...]]`, оглавление и обратные ссылки;
- Obsidian Bases: файлы `.base`, вложения `![[База.base]]`, фильтры, формулы, сортировка, группировка, агрегаты, таблицы, списки, карточки и доски;
- публичные папки, закрытые исключения и индивидуальные ссылки, которые можно отозвать.

Служебная папка `.obsidian` не синхронизируется. Это специально: настройки интерфейса и наборы плагинов на телефоне и компьютере могут отличаться.

## Конфиденциальность и сетевые подключения

Плагин использует сеть только для подключения к адресу сервера, который пользователь самостоятельно указывает в настройках. Телеметрии, аналитики, рекламы и подключений к сторонним сервисам нет.

- обычная синхронизация передаёт на самостоятельно размещённый сервер зашифрованные AES-256-GCM данные;
- ключ шифрования остаётся на устройствах и входит в секретный код подключения;
- имена и содержимое файлов основной синхронизируемой копии серверу недоступны;
- заметки веб-просмотрщика передаются серверу в открытом виде только после явного добавления пути в правила публикации;
- владелец сервера самостоятельно отвечает за его доступность, резервное копирование и сетевую безопасность.

Проект распространяется по лицензии [MIT](LICENSE).

## Публикация в каталоге Obsidian

После завершения тестирования:

1. Сделайте репозиторий публичным.
2. Создайте и отправьте тег, точно совпадающий с версией в `manifest.json`:

   ```bash
   VERSION=$(node -p "require('./manifest.json').version")
   git tag "$VERSION"
   git push origin "$VERSION"
   ```

3. GitHub Actions запустит официальный `obsidianmd/obsidian-workflows`, проверит проект правилами Community directory и создаст черновик GitHub Release с `main.js`, `manifest.json` и `styles.css`.
4. Проверьте черновик на странице Releases и опубликуйте его.
5. Войдите на [community.obsidian.md](https://community.obsidian.md), подключите GitHub и добавьте URL этого репозитория как новый плагин.

Для локальной проверки структуры публикации используйте:

```bash
npm run validate:submission
```

## 1. Развёртывание сервера на VPS

Сервер синхронизации и просмотрщик используют один настраиваемый порт. По умолчанию установщик выбирает первый свободный порт начиная с `18787` и привязывает его к `127.0.0.1`, не занимая 80/443 и не конфликтуя с уже установленным Nginx или Caddy.

### Установка одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/mirowin/simple-sync-obsidian/main/scripts/bootstrap-vps.sh | sudo bash -s -- --port auto
```

Свой порт можно указать сразу:

```bash
curl -fsSL https://raw.githubusercontent.com/mirowin/simple-sync-obsidian/main/scripts/bootstrap-vps.sh | sudo bash -s -- --port 19432
```

Скрипт:

- установит Docker Engine и Docker Compose из официального репозитория, если их ещё нет;
- скопирует сервер в `/opt/simple-sync-obsidian`;
- выберет свободный нестандартный порт или использует переданный через `--port`;
- сохранит настройки в `/etc/simple-sync-obsidian/config.env`;
- создаст `simple-sync-obsidian.service`;
- включит автозапуск после перезагрузки VPS;
- поднимет контейнеры и проверит `/health`.

Скрипт идемпотентный: его можно запускать повторно после обновления исходников.

Полезные команды:

```bash
sudo systemctl status simple-sync-obsidian
sudo systemctl restart simple-sync-obsidian
sudo journalctl -u simple-sync-obsidian -f
```

### Изменение порта после установки

Посмотреть текущие настройки:

```bash
simple-sync-config --show
```

Изменить порт с проверкой занятости и автоматическим перезапуском:

```bash
sudo simple-sync-config --port 19432
```

Также можно изменить `/etc/simple-sync-obsidian/config.env` вручную и выполнить:

```bash
sudo systemctl restart simple-sync-obsidian
```

### Подключение к существующему HTTPS reverse proxy

По умолчанию порт доступен только локально. Для Caddy достаточно добавить:

```caddyfile
sync.example.com {
    reverse_proxy 127.0.0.1:18787
}
```

Если при установке выбран другой порт, замените `18787` в конфигурации reverse proxy.

Для Nginx готов пример `deploy/nginx.conf.example`. После настройки reverse proxy в плагине указывается `https://sync.example.com`.

Если reverse proxy не нужен, сервер можно открыть напрямую, но соединение будет без TLS:

```bash
curl -fsSL https://raw.githubusercontent.com/mirowin/simple-sync-obsidian/main/scripts/bootstrap-vps.sh \
  | sudo bash -s -- --port 19432 --bind 0.0.0.0
```

В этом режиме установщик добавит выбранный порт в активный UFW. Для постоянной работы через интернет рекомендуется HTTPS reverse proxy.

Данные сохраняются в Docker volume `sync_data` и не исчезают при обновлении контейнера.

### Резервная копия серверных данных

```bash
docker run --rm -v simple-encrypted-sync_sync_data:/data -v "$PWD":/backup alpine \
  tar czf /backup/simple-sync-backup.tar.gz -C /data .
```

Имя volume можно проверить командой `docker volume ls`.

## 2. Установка плагина на компьютер

1. Закройте Obsidian.
2. Внутри нужного хранилища создайте каталог:

   `.obsidian/plugins/simple-encrypted-sync`

3. Распакуйте туда `manifest.json`, `main.js` и `styles.css` из плагин-архива.
4. Откройте Obsidian → **Настройки → Сторонние плагины**.
5. Отключите безопасный режим, если он включён, и активируйте **Simple Encrypted Sync**.
6. Откройте настройки плагина, укажите `https://sync.example.com` и нажмите **Создать**.
7. Скопируйте появившийся код подключения и сохраните его в менеджере паролей.

## 3. Установка на Android

1. Полностью закройте Obsidian.
2. В файловом менеджере включите отображение скрытых файлов.
3. В каталоге того хранилища, которое открывает Obsidian, создайте:

   `.obsidian/plugins/simple-encrypted-sync`

4. Распакуйте туда те же три файла: `manifest.json`, `main.js`, `styles.css`.
5. Запустите Obsidian → **Настройки → Сторонние плагины** и включите плагин.
6. В настройках плагина вставьте код с компьютера в поле **Код подключения** и нажмите **Подключить**.

Первое объединение может создать conflict-копию, если в одноимённых заметках на устройствах уже разное содержимое. Ничего не удаляется без сохранения изменённой версии.

## 4. Веб-просмотрщик и права

Основное хранилище остаётся зашифрованным. Для просмотра сервер получает отдельный открытый снимок только тех путей, которые разрешены правилами публикации.

Правило записывается одной строкой:

```text
public | Публичное
private | Публичное/Черновики
link | Семья | ключ-для-анны
link | Семья | другой-ключ-для-ивана
```

- `public` — любой посетитель может читать папку или файл;
- `link` — доступ есть только по адресу с `?key=секрет`;
- `private` — закрывает путь, даже если родительская папка открыта;
- более длинный, то есть более точный путь имеет приоритет;
- при одинаковом пути `private` имеет приоритет;
- несколько строк `link` для одного пути создают отдельный ключ каждому человеку.

Пример ссылки для Анны:

```text
https://sync.example.com/view/ИД-ХРАНИЛИЩА/?key=ключ-для-анны
```

Чтобы отозвать доступ только у Анны, удалите её строку `link` и нажмите **Опубликовать**. Остальные ссылки продолжат работать.

По умолчанию публикуется только папка `Публичное`. Чтобы открыть весь vault, укажите `public |` без пути. Это действие нужно использовать осторожно.

На втором устройстве публикация по умолчанию выключена, чтобы телефон случайно не перезаписал правила, настроенные на компьютере.

### Проводник, поиск и Obsidian Bases

Просмотрщик сохраняет структуру vault: папки и подпапки раскрываются как в проводнике Obsidian. Поиск выполняется не только по имени, но и по содержимому всех заметок, разрешённых текущему посетителю.

Файл Obsidian Bases можно открыть как самостоятельную страницу или вложить в Markdown:

```markdown
# Расходы

![[Money/БД.base]]
```

Запросы Bases выполняются только по доступным посетителю заметкам. Закрытые правилами `private` или недоступные без правильного `link`-ключа файлы не попадают в проводник, поисковый индекс, таблицы, формулы и агрегаты.

Поддерживаются представления `table`, `list`, `cards`, `gallery`, `board`/`kanban`, несколько вкладок в одном `.base`, глобальные и локальные фильтры, формулы, сортировка и стандартные summaries. Вычисление выражений использует MIT-компонент Quartz `@quartz-community/bases-page`.

## Ограничения MVP

- нет истории версий на сервере — есть только текущая версия и локальные conflict-копии;
- выдача доступа основана на индивидуальных секретных ссылках, без учётных записей и e-mail;
- DataviewJS намеренно не выполняется в общедоступном просмотрщике, поскольку это произвольный JavaScript;
- серверные бинарные блоки пока не удаляются автоматически после удаления заметок;
- публикация больших каталогов формирует один снимок, поэтому для медиатеки на десятки гигабайт понадобится потоковая публикация.

Для личного Obsidian и небольшой публичной базы знаний текущая схема рассчитана на простую установку и предсказуемое восстановление данных.
